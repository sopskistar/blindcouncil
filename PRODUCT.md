# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Native Hermes Desktop/Webapp extension: official @hermes/plugin-sdk, plain ESM plugin.js and host React. Python native gateway plugin, documented PluginContext registration and Hermes SQLite plugin storage. No standalone website or private renderer changes. The user's existing master specification fixes this stack; no additional framework choice is needed.

## Users

Coordinators who need two authorized people to decide on a sensitive project/release approval, with the coordinator also one participant in the MVP. Hackathon judges need a short, reproducible demonstration backed by genuine native Telegram evidence. No customers or production adoption are claimed.

## Product Purpose

Private decisions. Shared outcomes. A coordinator creates a named round; two allowlisted Telegram accounts receive separate private invitations and respond. Deterministic collect-both unanimity resolves it and notifies authorized participants. Persistent responses, message-bound identity checks and recoverable delivery reduce manual counting, message matching and failure follow-up.

## Operating Context

Windows11/WSL Ubuntu, one native Hermes Telegram gateway in an isolated home, one bot and two real configured accounts. Local Desktop/Webapp must bind to loopback and use Hermes authentication. Public publication requires the owner's approval. The user has already supplied product purpose, audience, stack, trust model, required flows, accessibility and autonomy instructions in PROJECT_MASTER_PLAN.md; initialization captures those confirmed answers without repeating an interview.

## Capabilities and Constraints

Verified: genuine two-account approval/rejection, duplicates, cancellation/expiry, wrong-message/revoked-participant denials, restart persistence and real blocked-bot recovery. Schema3 durable notification queue and CLI create/status/history/cancel/retry exist. Normal default24hours; supported presets15m/1h/24h/3d/7d. Exact deadlines never reset. No model can submit a vote through registered interfaces. Trusted host operators can access storage. Aggregate outcomes can permit inference. No E2EE, zero knowledge, independent-human, tamper-proof or exactly-once claim. No current action-bound or Hermes-wide enforcement.

## Brand Commitments

Working name BlindCouncil, retain unless a compelling verified collision. Clear, intentional experience comparable to Linear or Apple Notes; simple purpose/architecture/design/implementation. No generic metric dashboard, decorative cards, invented evidence or fake UI. Native Hermes controls/theme are authoritative within the host.

## Evidence on Hand

Original sanitized native JSON exports and hashes in docs/evidence; supporting55-method transcripts use actual Hermes SQLite with synthetic identities/transport. No product screenshots, rendered video, public demo, public GitHub or catalogPR yet. Do not fabricate missing material.

## Product Principles

1. Genuine authenticated human responses; deterministic policy rather than model guesses.
2. Persist consequential state and preserve failures/recovery evidence.
3. Share only permitted progress/aggregates and state the actual trust model.
4. Prefer documented native extension points and minimal product dependencies.
5. Prioritize verified installable functionality/submission before optional polish and future features.

## Accessibility & Inclusion

Visible keyboard focus, accessible names, semantic controls, understandable loading/empty/error states, sufficient contrast, responsive layout and reduced-motion support. Show text alongside state color; never rely solely on color or animation.
