# Hackathon README editorial standard

Use a judge-first, evidence-driven README. Before editing, inspect implemented source/features, current official rules/sponsor requirements, actual local/deployed application, demo, reports, architecture and limitations. Check whether submissions are open or judging/frozen; do not change submitted/frozen artifacts without confirming appropriateness.

Study Jennycruzy's Fieldwork, Eighty, Pledgebook, Twin and Page47 for structural lessons only. Write entirely original content for BlindCouncil. Open with a memorable accurate product explanation and a concrete human problem/purpose/audience. Put actual demo/source/judge walkthrough/proof links near the top; never invent missing destinations.

Walk through a complete implemented scenario. Explain manual tasks reduced, technically supported differentiation and Hermes' real contribution. Link important technical/numerical claims to reproducible evidence. Include test boundaries, deployment status and known limitations. Make the shortest successful judge demonstration clear. Preserve secure setup, architecture, useful technical docs and a concise repository map. Use purposeful screenshots/compact tables/architecture diagram when they clarify.

Never fabricate customers, usage, benchmarks, screenshots, transactions, integrations, awards or deployments. Separate implemented features, verified outcomes, synthetic demos, limits and future plans. No incomplete feature is presented as shipped. Avoid excessive badges/emojis/marketing or unnecessary length.

For editorial tasks, first report what works, what needs improvement and claims without evidence; then rewrite and verify all relative and external links against code. README-only commit unless separate application changes are explicitly authorized (the ongoing master build already authorizes staged product implementation). Preserve Git history/branches/credentials/submitted artifacts. Report exact changes and commit. Maintain this standard as new real functionality and media become available.
